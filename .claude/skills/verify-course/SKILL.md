# Проверка курса прогонами субагента

## Принцип

**Автор не может проверить свой курс, потому что молча чинит его на ходу.**

Это не гипотеза, а наблюдение. При проверке курса `graph-databases/` мастер-агент выполнил пример урока 11 как `MERGE (p:Product {sku:'CM-100'})`, хотя в уроке написано `CREATE`, — и не заметил, что оригинал нарушает ограничение уникальности из урока 9. Пример был сломан, проверка его пропустила. Независимый прогон нашёл это за минуту.

Отсюда схема: курс проходит **предвзятый субагент**, который выполняет текст буквально и не имеет права ничего исправлять. Мастер-агент только проверяет находки и правит. Цикл повторяется, потому что правки — сами по себе гипотезы, которые следующий прогон опровергает.

## Когда использовать

- Курс написан или существенно изменён, надо понять, проходится ли он
- Нужно оценить, хватает ли описания для настройки окружения
- Уроки ссылаются друг на друга и накапливают состояние (база, проект, файлы)

**Не нужно:** для отдельной статьи без практики, для курса без выполняемых примеров.

## Цикл

```
сброс окружения ──▶ прогон субагента ──▶ отчёт с находками
        ▲                                        │
        │                                        ▼
        └──── правки мастер-агента ◀──── проверка каждой находки
```

До **трёх итераций**. Каждая следующая проверяет в том числе правки предыдущей.

## Роль субагента: предвзятый студент

Ключ ко всему — формулировка запрета на додумывание. Без неё субагент ведёт себя как соавтор и молча обходит проблемы.

Обязательные пункты промпта:

1. **Выполняй команды ровно как написано, копипастой, без исправлений.**
2. **Падение или расхождение — это находка.** Зафиксируй урок, что обещано, что получилось, точный текст ошибки — и только ПОСЛЕ этого обходи проблему, чтобы двигаться дальше.
3. **Нехватка информации — тоже находка**, даже если ты знаешь ответ сам.
4. **Ты не редактируешь материалы курса.** Только проходишь и фиксируешь.
5. Явная граница: до какого урока идти, что не трогать.
6. Технические детали окружения (как запускать CLI, что уже установлено) — чтобы прогон не встал на ерунде.
7. **Не выдумывай находки ради объёма.** Чисто пройденный курс — допустимый результат.

Со второй итерации добавляй: «курс уже правили; не отчитывайся повторно о том, что теперь описано корректно; особое внимание местам, где текст даёт точное ожидаемое значение или явное предупреждение».

Формат отчёта: `урок N | что обещает текст | что произошло | серьёзность`. Плюс отдельным списком — что сошлось: это защищает от отчётов, где найдено «всё плохо» без разбора.

## Роль мастер-агента

**Проверяй каждую находку сам, прежде чем править.** Субагент ошибается и преувеличивает. Из отчёта первой итерации проверка подтвердила все восемь блокирующих находок — но узнать это можно было только повторив их своими руками (`javap` по jar драйвера, запуск контейнера с битой переменной, замер плана).

**Правки — гипотезы, а не факты.** В первой итерации мастер-агент предложил закрыть smoke-runner через `@Profile("!test")`. Следующий прогон показал, что слайс-тест этот профиль не активирует и совет не работает. Именно поэтому нужен второй прогон, а не один.

**Числа сверяй на эталонном состоянии.** Если в уроке приведён вывод, воспроизводи его на том состоянии данных, которое будет у студента к этому уроку, а не на своей накопленной базе.

## Сброс окружения обязателен

Перед каждым прогоном удаляй всё состояние: тома контейнеров, сгенерированные проекты, временные файлы. Прогон на прогретом окружении маскирует ровно тот класс проблем, ради которого всё затевается, — накопленное состояние из предыдущих уроков.

При этом само накопление состояния внутри одного прогона — это и есть предмет проверки: дубликаты, созданные практикой урока 6, ломают загрузку в уроке 9, и такое находится только сквозным проходом по порядку.

## Что искать: типовые классы находок

| Класс | Пример из реальной проверки |
|---|---|
| Команда не существует или сменила синтаксис | `ALTER DATABASE ... SET LANGUAGE` вместо `SET DEFAULT LANGUAGE` |
| Метод удалён в новой версии библиотеки | `withDriverMetrics()` из драйвера 5, отсутствует в 6 |
| Текст ошибки не совпадает с фактическим | обещано `Cannot delete node<42>...`, реально GQL-статус `G1001` |
| Пример опирается на данные, которых ещё нет | обход категории, создаваемой только в практике этого же урока |
| Инструмент требует флага, о котором не сказано | план запроса не виден без `--format verbose` |
| Функция редакции, поданная как доступная | query log работает только в Enterprise |
| Числа сняты на другом состоянии данных | вывод до генератора синтетики, практика — после |
| Задание не даёт обещанного эффекта | «зафиксируй ошибку» там, где ошибки не возникает |
| Порядок уроков ломает практику | задания требуют проекта из следующего трека |

## Условие остановки

Останавливайся, когда прогон даёт только:
- расхождения в числах, зависящих от случайности или версии;
- субъективные пожелания к подаче;
- находки, уже разобранные и осознанно отклонённые.

Не гоняй третью итерацию ради формальности, если вторая чистая. И не считай цикл успешным, пока остаются находки класса «блокирует прохождение».

## Частые ошибки

- **Один прогон вместо цикла.** Правки не проверены, часть из них неверна.
- **Правка по отчёту без собственной проверки.** Ломает работающий текст со слов агента.
- **Субагенту разрешено «поправить очевидную опечатку».** После этого он чинит всё подряд и молчит.
- **Прогон на прогретом окружении.** Половина класса находок недостижима.
- **Замена точных чисел на приблизительные везде.** Точное число — ценная проверка; заменяй только там, где оно зависит от состояния или `rand()`.
