Рассмотрим:

- Что такое класс инструментов prompt-to-UI и зачем он нужен Senior+
- v0.dev — компоненты для существующих React-проектов
- Bolt.new — генерация полного приложения в браузере через WebContainers
- Lovable — генерация SaaS-приложения с Lovable Cloud и Supabase
- Claude Design — чат и холст с передачей в Claude Code
- Google Stitch и DESIGN.md как отраслевой стандарт портативной дизайн-системы
- Pencil Dev — рой агентов и `.pen` с MCP в IDE
- Сравнение и матрица выбора инструмента
- Senior-практики: prompt engineering, итерации, реальная готовность к продакшену 60–85%
- Безопасность и привязка к вендору (vendor lock-in): что ломается в AI-сгенерированном коде на проде

## Класс инструментов prompt-to-UI: зачем это Senior+

В 2026 году prompt-to-UI — это не один инструмент, а целый класс. Внутри класса три подкласса по размеру результата:

### Три подкласса prompt-to-UI

- **Компоненты:** v0.dev. Один React-компонент под существующий Next.js-проект. Без бэкенда, без маршрутизации, без управления состоянием.
- **Полное приложение:** Bolt.new и Lovable. Готовое приложение с фронтендом, API, базой и аутентификацией — но внутри ограничений каждого инструмента.
- **Дизайн-первый подход:** Claude Design, Google Stitch, Pencil Dev. Артефакт — дизайн или прототип, который затем передаётся в Claude Code или Cursor для генерации продакшен-кода.

Для Senior-разработчика и архитектора эти инструменты — не способ заменить себя, а способ ускорить ту часть работы, которая всё равно делается руками каждую неделю: страницы тарифов, формы, дашборды, внутренние утилиты, MVP под проверку гипотезы.

### Что эти инструменты реально дают

- 60–85% готового к продакшену кода по умолчанию
- От 30 секунд до пары часов вместо 4–8 часов ручной вёрстки на компонент
- Встроенный shadcn/ui + Tailwind или близкие решения — единый визуальный язык в команде
- Экспорт в GitHub и возможность дальше править в обычной IDE

### Что они не дают

- Готовность к продакшену сразу. Отраслевой бенчмарк AI-сгенерированного кода — около 50% проектов содержат явные уязвимости (RLS отключён, API-ключи в клиентском бандле, webhook без подписи). Это данные на апрель 2026 года.
- Замену архитектурного ревью и ревью безопасности.
- Сложную бизнес-логику. На задачах сложнее CRUD и базовых форм качество вывода падает, и проще переходить в обычный Claude Code или Cursor.

Старый тезис **AI заменит фронтендеров** не сбылся, но появился более точный: AI забрал шаблонную работу (boilerplate), и Senior-роль сместилась к архитектуре, ревью безопасности и анализу компромиссов при выборе инструмента под задачу.

## v0.dev — компоненты для существующих React-проектов

v0.dev от Vercel — самый узкий по охвату инструмент в классе и при этом самый качественный по визуальному выводу. Он не пытается генерировать бэкенд или приложение целиком; задача — React-компонент в стеке Next.js + shadcn/ui + Tailwind CSS, который можно скопировать в существующий проект.

### Что v0 генерирует

- React-компонент на TypeScript
- Tailwind CSS для стилизации
- shadcn/ui для базовых элементов (карточка, кнопка, диалог и так далее)
- Иконки lucide-react
- Адаптивную вёрстку по умолчанию

### Что v0 не генерирует

- Бэкенд и API
- Маршрутизацию — это работа Next.js
- Управление состоянием сложнее useState
- Продакшен-конфиги (аутентификация, переменные окружения, развёртывание)

### Тарифы и модели на 2026 год

С начала 2026 года v0 перешёл на тарификацию по токенам вместо фиксированного лимита сообщений. Четыре модели с разными стоимостями:

- **Free:** \$5 в месяц (лимит 7 сообщений в день, доступ к v0 Mini, развёртывание в Vercel).
- **Team:** \$30 за пользователя в месяц (\$30 в месяц + \$2 ежедневного бонуса, общие кредиты, централизованный биллинг, нет лимита на сообщения).
- **Business:** \$100 за пользователя в месяц (всё из Team + тренинг-данные отключены по умолчанию).
- **Enterprise:** индивидуальные условия, SAML SSO, RBAC, SLA, данные не используются для обучения.

Модели (Mini → Pro → Max → Max Fast) дают разный баланс скорости и стоимости. Mini дешёв для простых компонентов, Max Fast работает в 2.5x раза быстрее Max, но дороже.

После перехода на тарификацию по токенам в начале 2026 года трафик v0 упал на 71%, и аналитики рассмотрели это как сигнал, что бесплатный план стал честнее: \$5 кредитов покрывают около 50 базовых генераций или 5–10 сложных, дальше — платно.

### Ключевая особенность v0

Фокус на визуальном качестве. v0 генерирует компоненты, которые с первой попытки выглядят как продакшен. Это объясняется специализацией: v0 натренирован именно на стек shadcn/ui + Tailwind, и он знает идиомы этого стека лучше универсальных кодогенераторов вроде Cursor или Claude Code.

### Сильный prompt для v0

Слабый prompt даёт типовой результат с несколькими итерациями:

```
Create a pricing table
```

Сильный prompt за одну итерацию даёт результат, готовый к продакшену:

```
Create a modern pricing card using shadcn/ui Card
component, with three tier options: Starter $20/mo,
Pro $50/mo, Enterprise custom. Include:
- Gradient border (purple to blue)
- Feature comparison with checkmarks
- Highlight "Pro" as recommended
- Responsive grid: mobile stack, desktop 3 columns
- Hover effect with subtle lift animation
```

### Интеграция в существующий проект

После генерации в v0 — копирование в проект и три команды установки зависимостей:

```bash
pnpm dlx shadcn@latest add card
pnpm add lucide-react
```

Дальше — обычный импорт компонента:

```typescript
import { PricingTable } from '@/components/PricingTable'

export default function Page() {
  return <PricingTable />
}
```

### Когда v0 подходит и когда нет

Подходит:

- Проект уже на Next.js + Tailwind + shadcn/ui
- Нужны страницы тарифов, дашборды, формы, таблицы, навигация, карточки
- Прототипы для дизайн-ревью
- Генерация внутренних утилит и админок

Не подходит:

- Стек не React или не Tailwind — переписывать придётся целиком
- Нужно полное приложение с бэкендом — это к Bolt.new или Lovable
- Сложная интерактивность вроде drag-and-drop или real-time

## Bolt.new — полное приложение в браузере через WebContainers

Bolt.new от StackBlitz — другой класс инструмента. Если v0 даёт компонент, Bolt.new даёт всё приложение, и оно запускается прямо в браузере. Без серверов, без виртуальных машин, без Docker, без локальной установки Node.js.

### Ключевая технология: WebContainers

**WebContainer** — это полноценный Node.js-runtime, скомпилированный в WebAssembly и работающий внутри вкладки браузера. Это не удалённая виртуальная машина и не облачный контейнер; это настоящий Node, выполняющий JavaScript на клиенте. Из этого следует:

- npm install работает в браузере
- сервер разработки стартует в той же вкладке
- терминал и файловая система доступны как в обычной IDE
- живой превью обновляется без сетевых задержек

WebContainers — собственная разработка StackBlitz, и это технологическое преимущество, которое конкуренты либо лицензируют, либо повторяют со значительными затратами.

### Что Bolt.new генерирует

- Фронтенд на React, Vue или Svelte (на выбор)
- Бэкенд на Node.js с Express или Fastify
- База — встроенный SQLite в браузере или внешний PostgreSQL
- Развёртывание в один клик в Netlify или Vercel
- Bolt V2 (вторая половина 2025 года) добавил встроенные базы данных, аутентификацию и хостинг прямо в платформу

### Тарифы и модели на 2026 год

Bolt.new использует token-based billing. Бесплатный план с лимитами, платные планы от \$20/месяц с возрастающим количеством включённых токенов. Точные цифры варьируются; главное отличие от v0 — Bolt включает полный бэкенд, поэтому сжигание токенов выше за сложность работы.

Реальные пользовательские расходы — \$50–200 в месяц на сложных проектах. Сжигание токенов — известная проблема: каждое сообщение синхронизирует всё файловое дерево в модель, и приложение из 50 файлов потребляет в разы больше токенов на итерацию, чем 5-файловая страница лендинга.

### Маршрутизация между моделями

В апреле 2026 Bolt.new маршрутизирует запросы между несколькими моделями: GPT-5.4, Claude Opus 4.7 и Gemini 3.1 Pro. Выбор модели зависит от задачи (простая правка против архитектурной генерации) и текущей нагрузки. Для пользователя это прозрачно, но имеет смысл понимать: за **одной кнопкой Generate** стоит маршрутизатор, а не одна модель.

### Практический пример: система бронирования за 2 часа

Вот prompt уровня **запустить и проверить гипотезу**:

```
Create a yoga studio booking system with:
- Studio owner dashboard
- Class schedule (calendar view)
- Customer booking flow
- Payment processing (Stripe integration)
- Email confirmations (automated)
- Mobile-responsive design
```

Через 2 часа итераций получается:

- работающий прототип с живыми тестовыми данными
- бэкенд API с конечными точками
- база со сгенерированной схемой
- платёжный поток в тестовом режиме Stripe
- развёрнутый URL для демонстрации

### Когда Bolt.new подходит и когда нет

Подходит:

- MVP с бэкендом за часы, не дни
- быстрая валидация идеи перед инвестициями в команду
- внутренние утилиты для команды
- прототипы для презентаций инвесторам

Не подходит:

- стек вне JavaScript-экосистемы — Python, Ruby, Go-бэкенды не запустятся
- сложная бизнес-логика (финансовые расчёты, налоговые алгоритмы, сложные процессы)
- мобильные приложения нативно — только веб
- нагрузка с требованиями к соответствию стандартам. Инфраструктура Bolt V2 новая (2025 год); сертификаций SOC2 / ISO на уровне платформы пока нет.

### WebContainers: ограничения, о которых нужно знать

- WebAssembly медленнее нативного Node. Большие приложения с тяжёлыми шагами сборки видимо тормозят по сравнению с локальной установкой.
- WebContainers не запустят нативные бинарники и npm-пакеты, требующие внутренностей Node.js.
- Вкладка браузера имеет лимиты по памяти, и проект на 100+ файлов начинает тормозить.

## Lovable — полное SaaS-приложение, Lovable Cloud и Supabase

Lovable — единственный prompt-to-UI инструмент с явной корпоративной сертификацией (SOC2 Type 2, ISO 27001:2022) и при этом самой жёсткой связкой со стеком. Если v0 — компоненты, Bolt.new — полное приложение с любым бэкендом, то Lovable — полное приложение строго на React + Tailwind + Supabase, и это осознанное архитектурное решение.

### История компании

- **2023:** GPT Engineer — open-source-проект, 51 тысяча звёзд на GitHub.
- **2024:** две неудачные попытки коммерческой версии.
- **Ноябрь 2024:** ребрендинг в Lovable.
- **2025–2026:** высокий спрос на no-code/AI-generated SaaS, массовое внедрение у стартапов и организаций, требующих быстрой валидации идей.
- **Инвестиции и рост:** за несколько месяцев после ребрендинга Lovable привлёк значительное финансирование и стал одной из популярных платформ для генерации приложений.

### Lovable Cloud: что изменилось в Lovable 2.0

Главное архитектурное изменение версии 2.0 (конец 2025 — начало 2026 года) — Lovable Cloud, встроенный бэкенд, который заменил внешний Supabase для большинства сценариев. До 2.0 пользователь сам конфигурировал Supabase, ключи и RLS; теперь это делается нативно одним prompt. Опция **подключить внешний Supabase** остаётся — её выбирают команды, у которых уже есть свой Supabase или кому нужен полный контроль.

Кроме Cloud, в 2.0 появились:

- **Agent Mode** — автономное планирование и исправление ошибок. По данным самого Lovable, ошибки сократились на 91%.
- **Visual Editor** — Figma-подобный интерфейс для быстрых правок без чата.
- **Dev Mode** — двусторонняя синхронизация с GitHub.
- **Security Scan** — встроенная проверка уязвимостей перед развёртыванием.

### Технологический стек

- **Фронтенд:** React 18+ с TypeScript, Tailwind CSS, shadcn/ui, сборка на Vite.
- **Бэкенд:** Lovable Cloud или Supabase (PostgreSQL).
- **Аутентификация:** Lovable Cloud Auth или Supabase Auth.
- **Хранилище:** Lovable Cloud Storage или Supabase Storage.
- **Real-time:** подписки через Cloud или Supabase Realtime.

### Тарифы на апрель 2026

- **Free:** 5 кредитов в день (около 30 в месяц), публичные проекты, 20 коллабораторов, 5 поддоменов на lovable.app.
- **Starter:** \$20 в месяц, 100 кредитов в месяц, 5 ежедневно, приватные проекты, собственные домены, режим кода, удаление маркера Lovable.
- **Launch:** \$50 в месяц, 500 кредитов в месяц, SSO, шаблоны дизайна, отказ от использования данных для обучения.
- **Scale:** \$100 в месяц, 1500 кредитов в месяц, приоритетная поддержка.
- **Enterprise:** индивидуальные условия, выделенная поддержка, индивидуальные интеграции.

### Реальное сжигание кредитов

Маркетинговое **5–10 фич в месяц на Pro плане** не совпадает с реальностью активного проекта. По данным разборов 2026 года:

- простой компонент: 1–2 кредита
- полная страница: 5–10 кредитов
- сложная фича (kanban, дашборд, CRUD): 20–50 кредитов
- цикл отладки при застревании AI: 50–200 кредитов

Активный проект — это 300–500 кредитов в месяц, то есть фактическая стоимость \$50–100, а не \$25. Это нужно закладывать в бюджет MVP с самого начала.

### Безопасность и соответствие требованиям

В отличие от конкурентов, Lovable имеет реальные сертификаты:

- **SOC2 Type 2** — подтверждено в журнале изменений Lovable.
- **ISO 27001:2022** — выдан Gradient Certification 8 мая 2025 года, наблюдательный аудит апрель 2026 года, ресертификация до 7 мая 2028 года. Документ публично доступен в Trust Center.
- **Security Center (v0.1)** — обзор находок по безопасности на уровне рабочего пространства: статусы анализа кода, предупреждения, уязвимости зависимостей с уровнями серьёзности.

При этом сертификации **самой платформы** не делают сгенерированные приложения безопасными — это критично для понимания.

### Когда Lovable подходит и когда нет

Подходит:

- Нетехнический фаундер строит SaaS MVP
- Быстрая валидация идеи перед наймом команды
- Внутренние утилиты с реальной базой и аутентификацией
- Прототипы для презентаций инвесторам и клиентам
- Организации, для которых важны SOC2 / ISO

Не подходит:

- Стек вне React + Tailwind + Supabase / Lovable Cloud — миграция дорогая
- Приложения с 30+ компонентами — известный **барьер 80%**, дальше AI деградирует
- Сложная бизнес-логика (финансовые расчёты, налоговые алгоритмы, сложные процессы)
- Мобильные приложения нативно — только веб
- готовность к продакшену по умолчанию 60–70%, остальное — ревью кода и упрочнение защиты (hardening)

## Claude Design — чат и холст с передачей в Claude Code

Claude Design запущен Anthropic Labs 17 апреля 2026 года в формате research preview. Это не ещё один генератор UI; это попытка закрыть петлю **идея → дизайн → код** внутри одной экосистемы Anthropic — Claude Design делает дизайн, Claude Code превращает его в продакшен-код, и контекст сохраняется на всём пути.

### Базовая механика: две панели

Интерфейс состоит из двух панелей:

- **Слева — чат.** Туда пишут prompt, загружают файлы (DOCX, PPTX, XLSX, изображения), привязывают кодовую базу и URL для веб-захвата.
- **Справа — холст.** На нём появляются сгенерированные дизайны: прототипы, каркасы экранов (wireframes), презентационные слайды (pitch decks), страницы лендингов, интерактивные сценарии.

Уточнение дизайна идёт тремя способами:

- Инструкции в чате
- Inline-комментарии прямо на холсте (клик по элементу — стрелка — текст)
- Прямые правки сгенерированного результата
- Пользовательские слайдеры, которые сам Claude строит на лету для подгонки цвета, отступа, типографики

### Чем Claude Design отличается от v0 / Bolt / Lovable

- **Авто-наследование дизайн-системы.** Если у организации есть фирменные цвета, шрифты, компоненты — Claude подтягивает их автоматически.
- **Импорт кодовой базы** через GitHub или локальную директорию. Claude видит существующие компоненты, архитектуру, стилистику и генерирует дизайн с учётом продакшен-кода.
- **Bundle для передачи** в Claude Code — главное отличие. Это не PNG и не Figma URL, а машинно-читаемый bundle: спецификация компонентов в структурированном виде, дизайн-токены, иерархия макета, ссылки на ассеты. Claude Code читает bundle напрямую, без распознавания пикселей.
- **Одно и то же семейство моделей.** Дизайн делает Opus 4.7, и код пишет Claude Code, использующий ту же серию моделей. Замысел дизайна сохраняется при переходе.

### Что генерирует Claude Design

- продуктовые каркасы экранов и макеты
- слайды презентаций
- одностраничные документы и страницы лендингов
- интерактивные прототипы приложений
- тесты с 3D, видео, голосом и встроенным кодом

### Экспорт

- ZIP с файлами дизайна
- PDF
- PPTX
- Canva
- автономный HTML
- bundle для Claude Code (главный сценарий)

### Доступ и тарификация

Доступен на Claude Pro, Max, Team, Enterprise. У Claude Design **отдельная недельная квота**, не общая с обычным Claude и Claude Code. Это важно учитывать при планировании дизайн-работы: дизайн не съест бюджет Claude Code.

### Реальный кейс из официального анонса

Brilliant использует Claude Design для интерактивных образовательных страниц с анимациями. В цитате из анонса:

> Наши самые сложные страницы, которые требовали 20+ prompts в других инструментах, теперь делаются за 2 prompts в Claude Design. Включение замысла дизайна в передачу Claude Code сделало переход прототип → продакшен бесшовным.

### Когда выбирать Claude Design

Подходит:

- Команда уже сидит в Claude Code — передача бесшовная
- Нужно быстро итерировать визуал на ранней стадии
- Продуктовый менеджер хочет описать фичу без UX-дизайнера и сразу передать инженеру
- Компании с собственной дизайн-системой — авто-наследование убирает повторное описание системы в каждом prompt

Не подходит:

- Продакшен без SLA — это research preview
- Автономный дизайн без последующего перехода в Claude Code (тогда выгоднее Stitch или Pencil)
- Интеграция с не-Anthropic инструментами — экспорт есть, но передача заточена под Claude Code

## Google Stitch и DESIGN.md как отраслевой стандарт

Google Stitch — экспериментальный инструмент дизайна от Google Labs. На фоне Claude Design он играет роль **открытой платформы**: Stitch не пытается закрыть всю петлю **дизайн → код** в одном вендоре, а делает ставку на портативные форматы и совместимость с Antigravity, AI Studio и сторонними IDE.

### Релизы марта–апреля 2026: что изменилось

- **18 марта 2026 — Vibe design with Stitch.** Stitch перешёл с плоского холста на бесконечный AI-нативный холст. Под капотом — Gemini 3, заметно улучшенная генерация UI.
- **3D-рабочее пространство.** Плоский холст заменён на иммерсивную среду для сложных UI/UX-сценариев со множеством экранов.
- **Голосовой дизайн через Gemini Live.** Голосовой интерфейс для критики дизайна и навигации по холсту. Compact-виджет с журналом действий для прозрачности.
- **Реальный экспорт в React.** Не кликабельный прототип, а полноценное React-приложение, которое можно экспортировать в AI Studio, Antigravity или другие инструменты разработки. Также доступен экспорт во Flutter и HTML/CSS.
- **Продвинутое прототипирование.** Навигация между экранами, QR-код для тестирования прототипа на телефоне.
- **Stitch MCP server.** Stitch предоставляет MCP-сервер с инструментами и навыками, что позволяет другим AI-ассистентам читать и менять Stitch-дизайны.

### DESIGN.md: 21 апреля 2026 — открыто на GitHub

DESIGN.md — это markdown-файл, описывающий дизайн-систему: цвета, типографику, компоненты, отступы, заметки о взаимодействии. До 21 апреля 2026 года формат был внутренним для Stitch. Затем Google открыл черновик спецификации на GitHub, и DESIGN.md перестал быть Stitch-специфичным.

Что это даёт:

- **Портативность.** Один DESIGN.md можно использовать в Stitch, IDE, Claude Code, Cursor, Antigravity. Это аналогия с CLAUDE.md / .cursorrules / AGENTS.md — единая механика markdown-инструкций для агентов.
- **Извлечение из URL.** Stitch умеет извлекать DESIGN.md из любой страницы одним кликом — есть готовая дизайн-система для адаптации.
- **Валидация по WCAG.** AI-агенты могут проверять свои дизайнерские решения против правил доступности — это снимает один из пунктов **чек-листа готовности к продакшену** автоматически.

### Тарифы

Stitch на апрель 2026 года — бесплатный экспериментальный продукт Google Labs. Лимит — 350 генераций в месяц. Это значительно щедрее v0 (\$5 кредитов), Lovable (\$20 / \$50 / \$100) и Bolt (\$20+). Полный анонс с финальной тарификацией ожидается на Google I/O 2026 (19–20 мая).

### Когда выбирать Stitch

Подходит:

- нужен интенсивный дизайн без бюджетных ограничений (350 генераций бесплатно)
- интеграция с экосистемой Google Cloud и AI Studio
- работа в команде, где DESIGN.md как переносимый формат — преимущество
- сложные многоэкранные прототипы с реальной навигацией

Не подходит:

- продакшен-проекты, требующие SLA — Stitch в статусе экспериментального продукта Google Labs
- команды, у которых уже есть Claude Code как основной инструмент — передача в Anthropic-стек бесшовнее у Claude Design
- зависимости от Material Design — Stitch заточен под Material Design 3, что хорошо для Android, но плохо для проектов с другой стилистикой

## Pencil Dev — рой агентов и `.pen` с MCP в IDE

Pencil Dev — инструмент дизайна, который физически живёт **внутри** IDE. Это не отдельный сайт и не настольное приложение в стиле Figma; это холст, встроенный в Claude Code, Cursor, VSCode, Windsurf, Codex CLI, Antigravity. Главный артефакт — `.pen`-файл, который лежит в git рядом с кодом.

### История и команда

Pencil основан Tom Krcha в 2025 году, поддержан Andreessen Horowitz через программу Speedrun. К апрелю 2026 года — 100k+ пользователей.

### Ключевая особенность: рой агентов

До 6 параллельных AI-агентов на одном холсте. Каждый агент:

- работает независимо
- генерирует свой вариант дизайна на основе одного брифа
- может использовать разную модель (Claude, GPT, Gemini)
- может иметь свой набор стилей, референсные изображения, ограничения дизайн-системы

Параллельно с работой агентов человек может руками редактировать холст, перетаскивать элементы, объединять варианты. Это качественно другой режим работы — не **один prompt → один результат**, а **один бриф → шесть вариантов параллельно → выбираем и комбинируем**.

### Формат `.pen`: дизайн-как-код

`.pen` — JSON-файл, который:

- лежит в git рядом с исходным кодом
- проходит ревью кода как код
- версионируется через обычные git-процессы
- читается AI-ассистентами через MCP

Это полная аналогия дизайна-как-кода с инфраструктурой-как-кодом: дизайн-артефакт превращён в текстовый формат, поддающийся управлению версиями и автоматизации.

### Интеграция с Claude Code через MCP

Pencil экспонирует свои дизайны через Model Context Protocol (протокол контекста модели) — Claude Code читает `.pen`-файлы и генерирует код по дизайну. Стандартный сценарий:

```
1. Запускаем Pencil и Claude Code
2. Открываем .pen-файл в Pencil
3. В Claude Code: /mcp → видим Pencil-инструменты
4. prompt: "Generate React code from the Dashboard
   Main frame in Pencil, using shadcn/ui"
5. Claude Code читает структуру дизайна — цвета,
   шрифты, отступы, иерархию макета — и генерирует
   код под нужный фреймворк
```

Pencil также имеет CLI-режим без графического интерфейса (`pencil` из терминала), что позволяет:

- запускать AI-агента с prompt из shell-скриптов
- пакетно обрабатывать множество дизайнов
- экспортировать в PNG, JPEG, WEBP, PDF

### Поддерживаемые IDE

Pencil интегрирован через MCP-сервер в:

- Claude Code (CLI и IDE)
- Claude Desktop
- Cursor
- VSCode
- Windsurf (Codeium)
- Codex CLI (OpenAI)
- Antigravity
- OpenCode CLI

### Когда выбирать Pencil

Подходит:

- Дизайн-как-код — команда хочет хранить дизайн в git, делать ревью дизайна, диффить изменения
- Агент-управляемый процесс с параллельным исследованием вариантов
- Работа с несколькими моделями одновременно для сравнения качества
- Интенсивная передача дизайн ↔ код через MCP

Не подходит:

- Интерактивные прототипы — Pencil даёт статический дизайн без анимаций и переходов
- Замена Figma в команде с дизайнерами — `.pen` зашифрован и не открывается в Figma
- Голосовое управление — нет (в отличие от Stitch)
- Работа без AI-ассистента — Pencil без MCP-интеграции теряет половину ценности

## Senior-практики: prompt engineering, итерации, реальная готовность к продакшену

Качество AI-сгенерированного UI зависит от двух вещей: что вы написали в prompt и как вы итерируете. Senior-разработчик отличается от Middle тем, что у него есть мета-практика — он знает, как структурировать prompt и когда остановиться.

### Структура эффективного prompt

Универсальная формула, работающая в v0, Bolt, Lovable и Claude Design:

```
[Context] +
[Component Type] +
[Visual Style] +
[Features] +
[Responsive Behavior] +
[Interactions]
```

Пример слабого prompt:

```
Create a dashboard
```

Пример сильного prompt:

```
Create a SaaS analytics dashboard.

Layout:
- Fixed sidebar 240px wide with logo, navigation,
  user profile section at the bottom
- Top header 64px with breadcrumbs, search bar,
  notifications icon, avatar
- Main content area with 24px padding

Content:
- 4 metric cards: Revenue (green accent), Users
  (blue), Conversion (purple), Churn (red)
- Line chart 700x400 showing revenue trend over
  30 days
- Transactions table with 5 columns: date,
  customer, amount, status badge, actions menu

Style:
- Dark theme, slate-800 background
- shadcn/ui components throughout
- Icons from lucide-react
- Inter font

Responsive:
- Mobile: sidebar collapses to hamburger menu
- Tablet: metric cards in 2 columns instead of 4
- Desktop: full 4-column layout
```

Сильный prompt даёт около 95% соответствия с первой попытки. Это значит на 5–10 итераций меньше, и при тарификации по токенам экономия — прямые деньги.

### Итеративный подход в 4 шага

Не нужно описывать всё в одном prompt — на сложных компонентах модель деградирует. Лучше работать по шагам:

```
Шаг 1 — Структура:
"Create a 3-column pricing table"

Шаг 2 — Контент:
"Add tiers: Starter $20, Pro $50, Enterprise
custom, with 5 features each"

Шаг 3 — Визуал:
"Highlight middle column with blue gradient
border and 'Most Popular' badge"

Шаг 4 — Интерактив:
"Add hover lift effect and monthly/yearly
billing toggle"
```

Каждый шаг — отдельная генерация. Ошибки от **смешения контекстов** убираются: модель не путает требования к макету с требованиями к интерактиву.

### Чек-лист готовности к продакшену

AI-сгенерированный код — это 60–85% готовности. Оставшиеся 15–40% — ручная работа Senior.

#### Безопасность

- Нет захардкоженных API-ключей в клиентском коде
- Пользовательский ввод санитизирован против XSS
- Проверки аутентификации на защищённых маршрутах
- Ограничение скорости на API-эндпоинтах
- Проверка подписи webhook для платёжных систем
- RLS-политики для всех таблиц с пользовательскими данными

#### Производительность

- Изображения оптимизированы (WebP, ленивая загрузка)
- Запросы к базе с LIMIT и индексами
- Разделение кода для больших компонентов
- Размер начального бандла менее 500KB
- Заголовки кэширования на статике

#### Доступность

- Навигация с клавиатуры работает для всех интерактивных элементов
- Индикаторы фокуса видимые (особенно на тёмной теме)
- Контрастность цветов не менее 4.5:1
- Альтернативный текст на всех значимых изображениях
- ARIA-метки там, где нужно
- Тестирование экранным диктором пройдено

#### Тестирование

- Юнит-тесты для критичной бизнес-логики
- Интеграционные тесты для основных пользовательских сценариев
- Ручное QA на минимум двух браузерах и трёх размерах экрана
- Smoke-тест на продакшене

### Когда выходить из prompt-to-UI в обычный Claude Code

Признаки, что вы упёрлись в потолок инструмента:

- одна и та же ошибка не уходит за 5+ итераций
- модель **переписывает работающие части** при попытке поправить одну
- сжигание токенов растёт нелинейно — на простую правку уходит больше кредитов, чем на исходную генерацию
- размер проекта приближается к 30+ компонентов (барьер Lovable) или 50+ файлов (потолок токенов Bolt)

В этой точке проще экспортировать проект в git и продолжить в обычной IDE с Claude Code или Cursor. Эти инструменты лучше держат большой контекст и точнее правят локальные баги.

### Типичные ошибки Middle-разработчика

- **Один prompt — готовое приложение.** Реальность: итеративный процесс из 5–20 шагов, как и обычная разработка.
- **Skip planning, AI разберётся.** Реальность: garbage in — garbage out. Чёткие требования дают лучший вывод.
- **100% AI-сгенерированный код значит готовность к продакшену.** Реальность: всегда нужно ревью кода, тесты, аудит безопасности.
- **AI заменит меня.** Реальность: AI забрал boilerplate. Senior-навыки — архитектура, анализ компромиссов, ревью безопасности — стали важнее, не менее значимы.

## Реальные риски: безопасность, привязка к вендору, скрытые расходы

Этот раздел — самый важный для архитектора и самый проблемный для маркетинга prompt-to-UI инструментов. На апрель 2026 года в публичном доступе есть конкретные инциденты, бенчмарки и паттерны, которых нельзя не знать, выбирая инструмент для команды.

### BOLA-уязвимость в Lovable, апрель 2026

20 апреля 2026 года была публично раскрыта уязвимость **Broken Object Level Authorization** (нарушенная авторизация на уровне объектов) в приложениях, построенных на Lovable. Суть: неавторизованные пользователи могли обращаться к данным, которые им не принадлежат, через бэкенд API без проверки разрешений. В JSON-ответах оказывались объекты, не предназначенные к публичному доступу.

Что особенно важно:

- Сообщено через HackerOne **за 48 дней до публичного раскрытия** — Lovable знал.
- **Частичный фикс только для новых проектов.** Легаси-проекты, созданные до ноября 2025 года, остаются уязвимыми.
- Реальный кейс — некоммерческая организация: учётные данные базы и пользовательские данные Supabase публично экспонированы.
- Lovable заявил, что не считает это **утечкой данных**.

Практический вывод для архитектора: AI-сгенерированный код требует независимого ревью безопасности. Сертификации платформы (SOC2, ISO 27001) защищают саму платформу, но не приложения, которые она сгенерировала.

### Инциденты безопасности в 2025 году

В 2025 году Lovable столкнулась с несколькими инцидентами, включая уязвимости в системных prompt-логиках, которые привели к утечке данных пользователей. Lovable своевременно публиковала отчёты и выпускала патчи. Важность этих инцидентов — демонстрация класса риска: когда платформа сама генерирует приложения по prompt-инструкциям, система уязвима к нарушениям на уровне платформы, а не только в сгенерированном коде.

### 12 типовых проблем приложений из подхода vibe coding

Анализ AI-сгенерированных приложений (на Lovable, Bolt и v0) в апреле 2026 года выявил 12 повторяющихся классов уязвимостей:

1. **Supabase RLS отключён.** Lovable создаёт таблицы, но не всегда включает Row-Level Security автоматически. Любой аутентифицированный пользователь видит всю базу.
2. **Сторонние API-ключи в клиентском коде.** Stripe, SendGrid, Twilio — ключи добавляются в prompt, попадают в React-компоненты, едят в браузер.
3. **Отсутствие валидации ввода.** Сгенерированные формы рендерят пользовательский ввод без санитизации — открыт XSS.
4. **Webhook без проверки подписи.** Платёжные webhook-обработчики принимают любой запрос без проверки подписи от Stripe / PayPal.
5. **Раскрытая структура базы.** SELECT * выдаёт колонки, которые должны были остаться скрытыми.
6. **Нет ограничения скорости.** Аутентификация и API-эндпоинты принимают неограниченное количество запросов — открыта дверь для подбора учётных данных (credential stuffing) и стоимостного DDoS на LLM-эндпоинты.
7. **Нет мягких удалений (soft delete).** Данные удаляются физически — восстановление невозможно.
8. **Слабая обработка ошибок.** Внутренние ошибки базы возвращаются клиенту с раскрытием схемы.
9. **JWT с длинным временем жизни.** Скомпрометированный токен живёт неделями.
10. **Anon-ключи в продакшен-сборке.** Невозможно использовать одну кодовую базу для staging и продакшена.
11. **Слишком широкие настройки CORS.** API открыт для любого источника.
12. **Нет аудит-логов.** Расследование инцидента без логов невозможно.

Это не редкие пограничные случаи — около 50% AI-сгенерированных приложений содержат как минимум одну из этих проблем по данным 2026 года.

### Скрытые расходы при масштабировании

Маркетинговые тарифы \$20–25 в месяц вводят в заблуждение. Реальный продакшен-стек на Lovable выглядит так:

```
Lovable Starter:        $20 / месяц
Реальное сжигание кред.: +$30 / месяц (300 кред.)
Собственный домен:       включено
Сервис рассылки:         +$10 / месяц (Resend)
Транзакции Stripe:       комиссии за транзакции
Доп. Supabase:           $25 / месяц при росте
                        (если не Lovable Cloud)

Итого реальная стоимость: $85+ в месяц
```

Сравнение с командой разработки на \$15 000+ в месяц действительно показывает экономию, но маркетинговое **\$25 / месяц** не отражает реальную совокупную стоимость владения.

### Гравитация вендора: ловушка GitHub-синхронизации

Все три инструмента полного приложения (Bolt, Lovable, v0) предлагают GitHub-синхронизацию и экспорт кода. На бумаге это значит **привязки к вендору нет**. На практике:

- Сгенерированный код использует специфичные паттерны инструмента (Lovable Cloud SDK, обёртки над Supabase).
- Итеративный агент опирается на свою историю правок — миграция в обычную IDE требует переноса контекста вручную.
- Собственные модификации в обычной IDE могут быть **переписаны** при следующей итерации агентом.

В результате: код экспортируется чисто, но полный переход с инструмента — это инженерный проект, а не **поменяли репозиторий**.

### Что делать архитектору

#### До выбора инструмента

- Заложить \$500–2000 на внешний аудит безопасности до запуска в продакшен
- Проверить, что инструмент покрывает 12 типовых уязвимостей в авто-режиме (Lovable Security Scan покрывает не все)
- Проверить требования соответствия организации против сертификаций инструмента (SOC2, ISO 27001, GDPR, HIPAA)

#### После генерации

- Прогнать сгенерированный код через статический анализатор (VibeScan, Snyk Code, Semgrep)
- Включить RLS на всех таблицах, ревью каждой политики руками
- Проверить, что webhook-обработчики проверяют подпись
- Установить ограничение скорости на аутентификацию и LLM-эндпоинты
- Добавить аудит-логирование критичных действий

#### Перед продакшеном

- Penetration-тестирование на минимум типовые векторы (BOLA, IDOR, prompt injection, XSS)
- Проверка бандла на наличие API-ключей через grep / scan
- Верификация сертификации соответствия через Trust Center, а не маркетинг

## Ключевые выводы

- **Класс prompt-to-UI расщепился на три подкласса в 2026 году:** компоненты (v0.dev), полное приложение (Bolt.new и Lovable), дизайн-первый подход (Claude Design, Google Stitch, Pencil Dev). Выбираем по реальной задаче — компонент в существующий проект, MVP с бэкендом под валидацию или дизайн с передачей в Claude Code — а не по маркетинговым обещаниям.

- **AI даёт 60–85% готовности к продакшену.** Оставшиеся 15–40% — безопасность, доступность, производительность, бизнес-логика. Отраслевой бенчмарк: около 50% AI-сгенерированных приложений содержат как минимум одну явную уязвимость из 12 типовых. Сертификации платформы (SOC2, ISO 27001) не защищают приложения, которые она сгенерировала.

- **DESIGN.md и bundle для передачи — два сигнала 2026 года.** DESIGN.md (Google Stitch) и bundle для Claude Code (Anthropic) — это про портативность дизайн-контекста, а не про лучшие генераторы UI. Markdown-инструкции для агентов — единая механика с CLAUDE.md / .cursorrules / AGENTS.md из Модуля 2.

- **Senior-роль смещается, не исчезает.** Меньше boilerplate-вёрстки, больше архитектуры, ревью безопасности, анализа компромиссов при выборе инструмента под задачу команды. AI не заменил Senior — AI забрал у Senior работу, которую Senior делать не хотел.

- **Реалистичная совокупная стоимость владения выше маркетинговых \$20–25 в месяц.** Реальный продакшен-стек — это \$85+ в месяц на небольшом проекте плюс одноразовый аудит безопасности на \$500–2000. Это всё равно несравнимо дешевле команды разработки, но планирование бюджета с цифры **\$20** ведёт к неприятным сюрпризам через месяц активной работы.
