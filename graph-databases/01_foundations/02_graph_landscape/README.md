# Урок 2. Ландшафт графовых решений

## Зачем разбираться в ландшафте

«Графовая база данных» — не одна технология, а два принципиально разных семейства моделей и десяток движков с разными языками запросов и моделями развёртывания. Выбор влияет на язык, на способ моделирования и на то, получится ли потом мигрировать. Этот урок даёт карту, чтобы дальше осознанно работать с Neo4j и понимать, чем пришлось бы заплатить при переходе на другое решение.

## Две модели: LPG и RDF

### Labeled Property Graph (LPG)

Модель Neo4j, Memgraph, TigerGraph. Узлы имеют метки и произвольный набор свойств, связи имеют тип и собственные свойства.

```
(:User {id: 42, name: "Анна", city: "Минск"})
    -[:PLACED {createdAt: "2026-03-01", channel: "mobile"}]->
(:Order {id: 1001, total: 4990})
```

Свойство на связи — естественный элемент модели. «Анна разместила заказ через мобильное приложение» выражается одной связью.

### RDF (Resource Description Framework)

Модель триплсторов: GraphDB, Stardog, Virtuoso, Amazon Neptune в режиме SPARQL. Всё представляется тройками «субъект — предикат — объект», где каждый элемент — URI.

```
<http://shop/user/42>  <http://shop/name>    "Анна" .
<http://shop/user/42>  <http://shop/placed>  <http://shop/order/1001> .
```

Свойств на связи нет. Чтобы сказать «заказ размещён через мобильное приложение», нужна реификация — превращение самой тройки в отдельный ресурс с дополнительными тройками. Это цена универсальности.

| Аспект | LPG | RDF |
|---|---|---|
| Идентификаторы | Внутренние, локальные | Глобальные URI |
| Свойства на связи | Нативные | Через реификацию |
| Язык запросов | Cypher, GQL, Gremlin | SPARQL |
| Схема | Опциональная | RDFS и OWL, формальные онтологии |
| Логический вывод | Нет из коробки | Reasoning по онтологии |
| Сильная сторона | Прикладные графы, производительность обходов | Интеграция данных между организациями, стандартизация |
| Типичное применение | Рекомендации, антифрод, зависимости | Публикация открытых данных, научные и медицинские онтологии |

Практический вывод: если задача — обходы внутри своей системы, бери LPG. RDF оправдан, когда нужны глобальные идентификаторы, обмен данными между организациями и формальный вывод по онтологии.

## Стандарт GQL

До 2024 года у графовых баз не было стандарта языка. Каждый вендор придумывал своё: Cypher у Neo4j, Gremlin в Apache TinkerPop, GSQL у TigerGraph, AQL у ArangoDB.

**GQL (ISO/IEC 39075)** — первый международный стандарт языка графовых запросов, опубликованный в 2024 году. Это второй язык запросов, стандартизованный ISO после SQL. Основой послужил Cypher: Neo4j передала его в открытую разработку через проект openCypher, и GQL вырос из него.

Что это значит на практике:

- Cypher 25 в Neo4j целенаправленно движется к соответствию GQL — часть синтаксиса уже изменена ради совместимости.
- Знание Cypher переносимо: openCypher поддерживают Memgraph, Amazon Neptune, Apache AGE, RedisGraph-совместимые движки.
- Полная переносимость запросов между вендорами пока не достигнута — стандарт молодой, реализации неполные.

## Основные движки

| Движок | Модель | Язык | Хранение | Особенность |
|---|---|---|---|---|
| **Neo4j** | LPG | Cypher, GQL | Диск с кэшем страниц | Самая зрелая экосистема, GDS, Java-драйверы, Spring Data |
| **Memgraph** | LPG | Cypher (openCypher) | In-memory | Совместим по языку с Neo4j, ориентирован на потоковые данные |
| **ArangoDB** | Мультимодель | AQL | Диск | Документы, графы и key-value в одной базе |
| **Amazon Neptune** | LPG + RDF | openCypher, Gremlin, SPARQL | Managed | Только в AWS, нет собственного развёртывания |
| **JanusGraph** | LPG | Gremlin | Cassandra, HBase, ScyllaDB | Горизонтальное масштабирование, требует отдельного бэкенда |
| **TigerGraph** | LPG | GSQL | Диск | Ориентация на аналитику по очень большим графам |
| **Apache AGE** | LPG | openCypher | PostgreSQL | Расширение для Postgres: граф и реляционка в одной базе |

### Когда что брать

- **Neo4j** — стандартный выбор для Java-стека: зрелые драйверы, Spring Data Neo4j, библиотека алгоритмов GDS, векторные индексы. Дальше вся программа про него.
- **Apache AGE** — когда граф нужен небольшой и уже есть PostgreSQL, а поднимать отдельную СУБД не хочется. Цена: заметно слабее производительность обходов и почти нет экосистемы.
- **Memgraph** — когда граф целиком помещается в память и важна скорость обновления из потока событий.
- **JanusGraph** — когда граф не помещается на один сервер, а бюджета на Neo4j Enterprise нет. Цена: сложная эксплуатация и Gremlin вместо Cypher.
- **Neptune** — когда инфраструктура целиком в AWS и не нужен контроль над версиями.

## Редакции Neo4j

| Редакция | Что даёт | Ограничения |
|---|---|---|
| **Community** | Полноценное ядро, Cypher, APOC, GDS, векторные индексы | Один инстанс без кластера, одна пользовательская база данных, нет ролевой модели доступа, нет онлайн-бэкапа |
| **Enterprise** | Кластер, множество баз данных, RBAC и права на уровне узлов, онлайн-бэкап, шардирование | Коммерческая лицензия |
| **Aura** | Управляемый сервис в облаке | Нет доступа к серверу, версии обновляет вендор |

Вся программа проходится на **Community** — её возможностей хватает для всего, кроме отдельных тем урока 24 (кластер, роли) и части алгоритмов GDS Enterprise. Такие места отмечаются явно.

> **Внимание**: одна пользовательская база в Community означает, что `CREATE DATABASE` не сработает. Разделять данные придётся метками или отдельными инстансами.

## Версионирование Neo4j и Cypher

С 2025 года Neo4j перешёл на **календарное версионирование**: формат `YYYY.MM.Patch`, новый релиз ежемесячно. Версия `2026.07.1` — релиз июля 2026 года, первый патч. Год не означает мажорную версию: релизы образуют один непрерывный поток без границ совместимости по годам.

Раз в 18-24 месяца один из релизов объявляется **LTS** и поддерживается минимум три года. Предыдущая LTS-ветка — `5.26`, она поддерживается параллельно с календарными релизами.

Одновременно язык запросов отделили от базы: у Cypher своя нумерация. Сейчас существуют две версии:

- **Cypher 5** — стабильная, изменений не будет, только исправления.
- **Cypher 25** — активная разработка, все новые возможности идут сюда, синтаксис приводится к GQL.

Версия языка выбирается независимо от версии базы: либо по умолчанию для базы данных, либо префиксом в запросе.

```cypher
// Выполнить конкретный запрос на Cypher 5, если он использует устаревший синтаксис
CYPHER 5 MATCH (n:User) RETURN n LIMIT 1;

// Явно указать Cypher 25
CYPHER 25 MATCH (n:User) RETURN n LIMIT 1;
```

Вся программа использует Cypher 25. Отличия от Cypher 5 разбираются в уроке 8.

## Практика

1. Запиши факт «Анна оценила товар на 4 звезды 1 марта» в модели LPG и в модели RDF. Сравни, сколько сущностей потребовалось в каждом случае.
2. Сформулируй для своего проекта, нужны ли глобальные идентификаторы и обмен данными с внешними организациями. Сделай вывод, LPG или RDF.
3. Открой список движков и выбери два, кроме Neo4j, которые теоретически подошли бы твоему проекту. Выпиши для каждого главный риск.
4. Проверь, какие ограничения Community станут блокирующими для твоего сценария, а какие обходятся.
5. Найди в документации Neo4j текущий LTS-релиз и сравни его дату с `2026.07`. Реши, какой вариант выбрал бы для продакшна и почему.
6. Объясни своими словами, почему стандартизация GQL не означает, что запросы автоматически переносимы между вендорами.

## Итоги урока

- Графовые БД делятся на два семейства: LPG с метками и свойствами на связях и RDF с тройками и глобальными URI.
- LPG подходит для прикладных графов внутри системы, RDF — для интеграции данных между организациями и формального вывода по онтологии.
- GQL (ISO/IEC 39075, 2024) — первый стандарт языка графовых запросов после SQL, вырос из Cypher через openCypher.
- Neo4j — самый зрелый вариант для Java-стека: Spring Data Neo4j, GDS, векторные индексы; Apache AGE подойдёт для небольшого графа поверх существующего PostgreSQL.
- Community даёт полное ядро без кластера, множества баз данных и ролевой модели — этого хватает для обучения и для многих продакшн-сценариев.
- Neo4j использует календарное версионирование `YYYY.MM.Patch` с ежемесячными релизами и LTS раз в 18-24 месяца.
- Версия языка Cypher отделена от версии базы: Cypher 5 заморожен, Cypher 25 развивается и приводится к GQL, выбор задаётся префиксом запроса или настройкой базы.
