# Урок 3. Запуск Neo4j и инструменты

## Что поднимаем

Одно окружение на всю программу: Neo4j Community с плагинами APOC и Graph Data Science, плюс Ollama для локальных эмбеддингов в треке 6. Файл `compose.yml` лежит в корне `graph-databases/`.

```
┌──────────────────────────────────────────────┐
│              контейнер neo4j                 │
│                                              │
│   :7474  HTTP ──▶ Neo4j Browser, Query API   │
│   :7687  Bolt ──▶ драйверы, cypher-shell     │
│                                              │
│   ┌────────────────────────────────────┐     │
│   │  ядро Neo4j 2026.07 Community      │     │
│   │  ├─ плагин apoc                    │     │
│   │  └─ плагин graph-data-science      │     │
│   └────────────────────────────────────┘     │
│                                              │
│   /data     ──▶ том neo4j-data               │
│   /logs     ──▶ том neo4j-logs               │
│   /import   ──▶ ./dataset (CSV для LOAD CSV) │
└──────────────────────────────────────────────┘
```

## Два протокола доступа

- **HTTP (порт 7474)** — Neo4j Browser и HTTP Query API. Через браузер удобно исследовать граф визуально.
- **Bolt (порт 7687)** — бинарный протокол Neo4j. По нему работают `cypher-shell`, Java Driver и Spring Data Neo4j. В продакшне приложение всегда ходит по Bolt.

URI подключения выглядят так:

| Схема | Когда использовать |
|---|---|
| `bolt://localhost:7687` | Прямое подключение к одному инстансу |
| `neo4j://localhost:7687` | Подключение с маршрутизацией — драйвер сам разошлёт запросы по кластеру |
| `bolt+s://`, `neo4j+s://` | То же самое с обязательным TLS и проверкой сертификата |

Локально работают обе схемы. В программе используется `bolt://`, а различия между ними разбираются в уроке 24.

## Разбор compose.yml

```yaml
services:
  neo4j:
    image: neo4j:2026.07.1-community
    environment:
      - NEO4J_AUTH=neo4j/graphpassword
      - NEO4J_PLUGINS=["apoc","graph-data-science"]
      - NEO4J_apoc_import_file_enabled=true
      - NEO4J_server_memory_pagecache_size=1G
      - NEO4J_server_memory_heap_initial__size=1G
      - NEO4J_server_memory_heap_max__size=2G
```

### Как переменные окружения превращаются в настройки

Neo4j читает конфигурацию из `neo4j.conf`, но в Docker её задают переменными окружения по строгому правилу:

1. Добавь префикс `NEO4J_`.
2. Точку в имени настройки замени на подчёркивание.
3. Подчёркивание в имени настройки замени на **двойное** подчёркивание.

| Настройка в `neo4j.conf` | Переменная окружения |
|---|---|
| `server.memory.pagecache.size` | `NEO4J_server_memory_pagecache_size` |
| `server.memory.heap.max_size` | `NEO4J_server_memory_heap_max__size` |
| `dbms.security.auth_enabled` | `NEO4J_dbms_security_auth__enabled` |

> **Внимание**: перепутанное количество подчёркиваний — самая частая ошибка при настройке Neo4j в Docker. Опечатка в имени настройки роняет контейнер на старте — включена строгая валидация конфигурации:
>
> ```
> Failed to read config
> Unrecognized setting. No declared setting with name: server.memory.pagecache_size.
> Cleanup the config or disable 'server.config.strict_validation.enabled' to continue.
> ```
>
> Это лучше молчаливого игнорирования, но означает, что при непонятном crash-loop первым делом надо смотреть `docker compose logs neo4j`, а не искать проблему в данных. Применённые значения проверяются запросом к `dbms.listConfig`.

### Память

У Neo4j два независимых пула памяти, и их роли отличаются от привычных по PostgreSQL.

| Пул | За что отвечает | Как подбирать |
|---|---|---|
| **Page cache** | Кэш страниц графа с диска: узлы, связи, свойства, индексы | В идеале равен размеру графа на диске — тогда обходы не задевают диск |
| **Heap** | Промежуточные результаты запросов, проекции GDS, транзакции | Растёт от сложности запросов и объёма данных в транзакции, а не от размера графа |

Для датасета этой программы хватает 1 ГБ page cache и 2 ГБ heap. На реальном графе размер подбирают командой `neo4j-admin server memory-recommendation`.

### Плагины

`NEO4J_PLUGINS` — механизм образа Neo4j: при старте контейнер ставит плагины в версии, соответствующей ядру, и сам прописывает нужные разрешения на выполнение процедур. Патч-версии при этом могут отличаться — на ядре `2026.07.1` нормально увидеть GDS `2026.07.0`.

| Плагин | Что даёт |
|---|---|
| `apoc` | Библиотека процедур: загрузка данных, работа с метаданными, батчевые операции, конвертации |
| `graph-data-science` | Графовые алгоритмы: центральности, сообщества, similarity, поиск путей |

В образе Neo4j jar-файлы APOC и GDS уже лежат внутри — при старте контейнер копирует их из `/var/lib/neo4j/labs` и `/var/lib/neo4j/products` в `/var/lib/neo4j/plugins` и прописывает разрешения. В логах это видно строкой `Installing Plugin 'apoc' from /var/lib/neo4j/labs/apoc-*-core.jar`. Для плагинов не из образа механизм действительно скачивает jar из интернета. Каталог `/plugins` намеренно не монтируется томом: при обновлении версии Neo4j файлы ставятся заново, и устаревший плагин не остаётся.

> **Важно**: не прописывай `dbms.security.procedures.unrestricted` вручную — механизм `NEO4J_PLUGINS` настраивает разрешения сам, а ручное значение их перетирает.

## Запуск

```bash
# Треки 1-5
docker compose up -d

# Трек 6 — дополнительно поднимает Ollama
docker compose --profile rag up -d

# Дождаться готовности (healthcheck делает реальный запрос, а не просто проверяет порт)
docker compose ps
```

Сервис `ollama` вынесен в профиль `rag` и по умолчанию не поднимается — на треках 1-5 он не нужен и только занимает ресурсы.

## cypher-shell

Основной инструмент для практики. Запускается внутри контейнера:

```bash
docker exec -it neo4j cypher-shell -u neo4j -p graphpassword
```

```cypher
// Версия ядра, редакция и версии компонентов
CALL dbms.components();

// Проверка, что APOC установлен
RETURN apoc.version();

// Проверка, что GDS установлен
RETURN gds.version();

// Идентификатор, имя и дата создания текущей базы
CALL db.info();

// Версия Cypher по умолчанию для базы — колонка defaultLanguage
SHOW DATABASES YIELD name, defaultLanguage;
```

Полезные команды самой оболочки — они начинаются с двоеточия и не являются Cypher:

| Команда | Действие |
|---|---|
| `:help` | Список команд |
| `:param name => 'Анна'` | Задать параметр запроса |
| `:params` | Показать заданные параметры |
| `:exit` | Выход |

Однократный запрос без входа в интерактивный режим:

```bash
docker exec -it neo4j cypher-shell -u neo4j -p graphpassword \
  "MATCH (n) RETURN count(n) AS nodes;"
```

> **Важно**: по умолчанию `cypher-shell` печатает только результат и сводку. Таблицу операторов плана запроса (`EXPLAIN` и `PROFILE` из урока 13) он не показывает без флага `--format verbose`:
>
> ```bash
> docker exec -it neo4j cypher-shell -u neo4j -p graphpassword --format verbose \
>   "PROFILE MATCH (n) RETURN count(n);"
> ```
>
> В интерактивном режиме флаг задаётся при запуске оболочки. Альтернатива — Neo4j Browser, он рисует план схемой всегда.

## Neo4j Browser

Открывается на `http://localhost:7474`, подключение — `bolt://localhost:7687`, логин `neo4j`, пароль `graphpassword`.

Что даёт помимо выполнения запросов:

- **Визуализация результата**: если запрос возвращает узлы и связи, Browser рисует граф, и по нему можно кликать, разворачивая соседей. На этапе изучения модели это быстрее любого текстового вывода.
- **Сводка по базе**: команда `:schema` показывает метки, типы связей, индексы и ограничения.
- **История запросов** и сохранённые скрипты.

```cypher
// Что вообще есть в базе — метки, типы связей, счётчики
CALL db.labels();
CALL db.relationshipTypes();
CALL db.schema.visualization();
```

> **Важно**: Browser рисует ограниченное число узлов (по умолчанию 300). Пустая картинка при непустом результате обычно означает, что запрос вернул скалярные значения, а не узлы — граф рисуется только для узлов и связей.

## Служебные запросы

```cypher
// Применённая конфигурация — так проверяются переменные окружения
CALL dbms.listConfig() YIELD name, value
WHERE name STARTS WITH 'server.memory'
RETURN name, value;

// Список баз данных. В Community их две: system и neo4j
SHOW DATABASES;

// Активные запросы — пригодится, когда что-то зависнет
SHOW TRANSACTIONS;

// Размер графа
MATCH (n) RETURN count(n) AS nodes;
MATCH ()-[r]->() RETURN count(r) AS relationships;
```

## Полная очистка

Пригодится, если эксперименты завели базу в непонятное состояние.

```bash
# Удалить контейнеры вместе с томами — граф будет потерян
docker compose down -v
docker compose up -d
```

Мягкий вариант, без пересоздания контейнера:

```cypher
// Удалить все узлы и связи. На больших графах так делать нельзя —
// вся операция идёт одной транзакцией и упрётся в heap
MATCH (n) DETACH DELETE n;
```

Батчевый вариант для больших объёмов разбирается в уроке 14.

## Практика

1. Подними окружение через `docker compose up -d` и дождись статуса `healthy` в `docker compose ps`.
2. Подключись через `cypher-shell` и выполни `CALL dbms.components()` — зафиксируй версию ядра и редакцию.
3. Проверь установку плагинов запросами `RETURN apoc.version()` и `RETURN gds.version()`.
4. Выполни `CALL dbms.listConfig()` с фильтром по `server.memory` и убедись, что значения из `compose.yml` действительно применились.
5. Намеренно сломай одну переменную в `compose.yml` — например, напиши `NEO4J_server_memory_pagecache__size` с двойным подчёркиванием — и перезапусти контейнер. Найди в `docker compose logs neo4j` сообщение о нераспознанной настройке и убедись, что база вообще не поднялась. Верни как было.
6. Открой Neo4j Browser, подключись и выполни `:schema` на пустой базе.
7. Выполни `SHOW DATABASES` и убедись, что пользовательская база ровно одна — это ограничение Community.
8. Создай один узел `CREATE (:Ping {at: datetime()})`, найди его в Browser, затем удали через `MATCH (n:Ping) DETACH DELETE n`.

## Итоги урока

- Neo4j слушает два порта: HTTP 7474 для Browser и Bolt 7687 для драйверов и `cypher-shell`.
- Схема `bolt://` подключается к одному инстансу, `neo4j://` включает маршрутизацию по кластеру, суффикс `+s` требует TLS.
- Настройки в Docker задаются переменными с префиксом `NEO4J_`, где точка становится подчёркиванием, а подчёркивание — двойным подчёркиванием; ошибка в правиле роняет контейнер на старте из-за строгой валидации конфигурации.
- Page cache кэширует граф с диска и подбирается по размеру данных, heap обслуживает запросы и проекции GDS и подбирается по их сложности.
- `NEO4J_PLUGINS` ставит APOC и GDS из jar-файлов образа и сам настраивает разрешения на процедуры — вручную их прописывать нельзя.
- `cypher-shell` — основной инструмент практики, Neo4j Browser нужен для визуального исследования графа и команды `:schema`.
- Таблица операторов плана в `cypher-shell` появляется только с флагом `--format verbose`; без него `PROFILE` выводит лишь общую сводку.
- `dbms.listConfig` — единственный надёжный способ проверить, что настройка из `compose.yml` действительно применилась.
- В Community ровно одна пользовательская база данных, `CREATE DATABASE` недоступен.
