# Урок 5. Cypher: чтение данных

## Что такое Cypher

Cypher — декларативный язык запросов к графу. Ключевая идея — **ASCII-art паттерны**: структура запроса визуально повторяет структуру графа.

```
(a)-[:REL]->(b)
 │     │      │
 узел  связь  узел
```

Круглые скобки — узел, квадратные — связь, стрелка — направление. Запрос описывает форму подграфа, который надо найти; как именно его искать, решает планировщик.

Данные для примеров созданы в уроке 4 — скриптом из раздела «Первые данные» и заданиями практики. Если ты выполнял ещё и отдельные примеры из теории урока 4 (они создают дополнительных пользователей и второй узел с `sku: 'CM-100'`), в выдаче будет больше строк, чем в примерах ниже: сверяй форму результата, а не количество. Если база пуста, вернись и выполни скрипт оттуда.

## MATCH и структура паттерна

```cypher
MATCH (u:User)
RETURN u.name, u.email;
```

`MATCH` описывает паттерн, `RETURN` — что вернуть. Cypher находит **все** подграфы, подходящие под паттерн, и возвращает по строке на каждое совпадение.

Полная анатомия паттерна:

```cypher
MATCH (u:User {name: 'Анна'})-[r:PLACED]->(o:Order)
RETURN u.name, r.channel, o.id;
```

| Часть | Что означает |
|---|---|
| `u`, `r`, `o` | Переменные — имена, по которым потом обращаться к найденному |
| `:User`, `:Order` | Метки узлов, ограничивают область поиска |
| `:PLACED` | Тип связи |
| `{name: 'Анна'}` | Inline-фильтр по свойствам |
| `-[...]->` | Направление связи |

Переменную можно не задавать, если она не нужна в результате:

```cypher
// Заказ нужен только как промежуточный шаг, переменная не заводится
MATCH (u:User)-[:PLACED]->(:Order)-[:CONTAINS]->(p:Product)
RETURN u.name, p.title;
```

Это не косметика: неиспользуемые переменные заставляют планировщик тянуть лишние данные.

## Формы паттернов

```cypher
// Цепочка: пользователь → заказ → товар → категория
MATCH (u:User)-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product)-[:IN_CATEGORY]->(c:Category)
RETURN u.name, p.title, c.name;

// Развилка: у одного заказа несколько товаров — по строке на каждый
MATCH (o:Order {id: 1001})-[:CONTAINS]->(p:Product)
RETURN o.id, p.title;

// Несколько типов связей через вертикальную черту
MATCH (u:User)-[:PLACED|REFERRED]->(x)
RETURN u.name, labels(x) AS targetType;

// Связь любого типа
MATCH (u:User {name: 'Анна'})-[r]->(x)
RETURN type(r) AS relType, labels(x) AS targetLabels;

// Несколько паттернов через запятую — соединяются по общим переменным
MATCH (u:User)-[:PLACED]->(o:Order), (o)-[:CONTAINS]->(p:Product)
RETURN u.name, o.id, p.title;
```

> **Важно**: одна и та же связь не может участвовать в одном паттерне дважды. Это правило (relationship uniqueness) избавляет от бесконечных циклов, но иногда даёт неожиданно пустой результат — если кажется, что совпадение должно быть, проверь, не используется ли одно ребро повторно.

## WHERE

Условия, которые не выражаются inline-фильтром.

```cypher
MATCH (p:Product)
WHERE p.price > 3000 AND p.price <= 10000
RETURN p.sku, p.title, p.price;
```

Inline-фильтр `{price: 4990}` работает только на точное равенство. Всё остальное — в `WHERE`.

### Операторы

```cypher
// Строки
MATCH (p:Product)
WHERE p.title STARTS WITH 'Кофе'
   OR p.title ENDS WITH 'Fine'
   OR p.title CONTAINS 'варка'
RETURN p.title;

// Регулярное выражение
MATCH (u:User) WHERE u.email =~ '.*@shop\\.io' RETURN u.email;

// Вхождение в список
MATCH (p:Product) WHERE p.sku IN ['CM-100', 'GR-200'] RETURN p.title;

// Наличие и отсутствие свойства
MATCH (p:Product) WHERE p.discount IS NOT NULL RETURN p.sku;
MATCH (p:Product) WHERE p.discount IS NULL     RETURN p.sku;

// Проверка метки
MATCH (n) WHERE n:Product AND n:Bestseller RETURN n.title;
```

### Фильтрация по наличию связи

Самая графовая часть `WHERE` — паттерн в условии.

```cypher
// Товары, которые кто-то покупал
MATCH (p:Product)
WHERE (:Order)-[:CONTAINS]->(p)
RETURN p.title;

// Товары, которые никто не покупал — паттерн под NOT
MATCH (p:Product)
WHERE NOT (:Order)-[:CONTAINS]->(p)
RETURN p.title;

// Пользователи, которые ничего не заказывали
MATCH (u:User)
WHERE NOT (u)-[:PLACED]->(:Order)
RETURN u.name;
```

Аналог в SQL — `NOT EXISTS` с подзапросом. В Cypher это часть того же языка паттернов.

Развёрнутая форма через `EXISTS {}` нужна, когда внутри требуется дополнительное условие:

```cypher
// Пользователи, у которых есть доставленный заказ дороже 5000
MATCH (u:User)
WHERE EXISTS {
  MATCH (u)-[:PLACED]->(o:Order)
  WHERE o.status = 'delivered' AND o.total > 5000
}
RETURN u.name;
```

## OPTIONAL MATCH

Аналог `LEFT JOIN`: если совпадения нет, переменные получают `null`, но строка не пропадает.

```cypher
// Все пользователи, у кого-то заказов может не быть
MATCH (u:User)
OPTIONAL MATCH (u)-[:PLACED]->(o:Order)
RETURN u.name, o.id, o.total;
```

```
╒═══════╤═════╤═══════╕
│u.name │o.id │o.total│
╞═══════╪═════╪═══════╡
│"Анна" │1001 │7480.0 │
│"Иван" │1002 │4990.0 │
│"Пётр" │null │null   │
└───────┴─────┴───────┘
```

> **Внимание**: `OPTIONAL MATCH` нельзя ставить первым в запросе — ему нужна уже найденная переменная, к которой он привязывается. И порядок важен: всё, что идёт после `OPTIONAL MATCH`, работает с возможными `null`.

## RETURN

```cypher
// Свойства
MATCH (p:Product) RETURN p.sku, p.title;

// Узел целиком — вернётся со всеми свойствами, в Browser нарисуется кружком
MATCH (p:Product) RETURN p;

// Псевдонимы
MATCH (p:Product) RETURN p.sku AS sku, p.price AS price;

// Выражения
MATCH (p:Product) RETURN p.title, round(p.price * 0.9) AS discounted;

// Служебные функции
MATCH (u:User)-[r:PLACED]->(o:Order)
RETURN labels(u) AS labels, type(r) AS relType, keys(o) AS orderProps;

// Уникальные значения
MATCH (:Order)-[:CONTAINS]->(p:Product)
RETURN DISTINCT p.title;
```

`RETURN *` возвращает все переменные, объявленные в запросе — удобно при отладке, но в приложении так писать не стоит.

## Агрегации

Агрегатные функции группируют **автоматически**: группировкой становятся все неагрегированные выражения в `RETURN`. Отдельного `GROUP BY` в Cypher нет.

```cypher
// Сколько заказов у каждого пользователя.
// Группировка по u.name — потому что это единственное неагрегированное выражение
MATCH (u:User)-[:PLACED]->(o:Order)
RETURN u.name, count(o) AS orders, sum(o.total) AS revenue;
```

| Функция | Что делает |
|---|---|
| `count(x)` | Количество непустых значений |
| `count(*)` | Количество строк |
| `sum`, `avg`, `min`, `max` | Числовые агрегаты |
| `collect(x)` | Собирает значения в список |
| `stDev(x)` | Стандартное отклонение |

`collect()` — самая полезная в графе: сворачивает несколько строк в одну со списком.

```cypher
MATCH (u:User)-[:PLACED]->(:Order)-[:CONTAINS]->(p:Product)
RETURN u.name AS user, collect(DISTINCT p.title) AS products, count(DISTINCT p) AS uniqueProducts;
```

> **Важно**: разница между `count(x)` и `count(*)` проявляется после `OPTIONAL MATCH`. `count(o)` не посчитает `null`, `count(*)` посчитает строку. Пользователь без заказов даст `count(o) = 0` и `count(*) = 1`.

```cypher
// Правильный подсчёт заказов, включая пользователей без заказов
MATCH (u:User)
OPTIONAL MATCH (u)-[:PLACED]->(o:Order)
RETURN u.name, count(o) AS orders;
```

## ORDER BY, SKIP, LIMIT

```cypher
MATCH (p:Product)
RETURN p.title, p.price
ORDER BY p.price DESC, p.title ASC
SKIP 0 LIMIT 10;
```

Сортировка по агрегату работает без дополнительных конструкций:

```cypher
MATCH (u:User)-[:PLACED]->(o:Order)
RETURN u.name, sum(o.total) AS revenue
ORDER BY revenue DESC
LIMIT 5;
```

> **Внимание**: `null` при сортировке по возрастанию идёт в конец, при сортировке по убыванию — в начало. При постраничном выводе это регулярно даёт «пропавшие» записи на границе страниц.

## Параметры

Значения в запрос подставляются параметрами, а не конкатенацией строк. Причины две: защита от инъекций и попадание в кэш планов — запрос с параметром планируется один раз, запрос со вклеенным значением планируется заново при каждом новом значении.

```cypher
// В cypher-shell параметр задаётся отдельной командой
:param email => 'anna@shop.io'
:param minPrice => 3000

MATCH (u:User {email: $email})-[:PLACED]->(:Order)-[:CONTAINS]->(p:Product)
WHERE p.price > $minPrice
RETURN p.title, p.price;
```

Влияние на производительность разбирается в уроке 14, но привычку писать `$param` стоит выработать сразу.

## Сравнение с SQL

| Задача | SQL | Cypher |
|---|---|---|
| Источник данных | `FROM users` | `MATCH (u:User)` |
| Соединение | `JOIN orders ON ...` | `-[:PLACED]->(o:Order)` |
| Фильтр | `WHERE` | `WHERE` или inline `{...}` |
| Группировка | `GROUP BY` явно | Неявно по неагрегированным полям |
| Внешнее соединение | `LEFT JOIN` | `OPTIONAL MATCH` |
| Проверка наличия | `EXISTS (SELECT ...)` | Паттерн в `WHERE` или `EXISTS {}` |
| Уникальность | `DISTINCT` | `DISTINCT` |
| Пагинация | `LIMIT/OFFSET` | `SKIP/LIMIT` |

## Практика

1. Выведи всех пользователей с почтой и датой регистрации, отсортировав по дате от новых к старым.
2. Найди товары дороже 3000, у которых в названии встречается «Кофе».
3. Выведи для каждого заказа список названий товаров одной строкой через `collect()`.
4. Найди товары, которые ни разу не попали ни в один заказ.
5. Выведи всех пользователей и количество их заказов так, чтобы пользователи без заказов тоже попали в результат с нулём.
6. Найди пользователей, у которых есть хотя бы один заказ в статусе `delivered` дороже 5000, через `EXISTS {}`.
7. Посчитай суммарную выручку по каждой категории товаров, используя `priceAtPurchase` и `qty` со связи `CONTAINS`.
8. Перепиши запрос из задания 2 с использованием параметров вместо литералов и проверь через `:params`, что они заданы.

## Итоги урока

- Cypher описывает форму искомого подграфа ASCII-паттерном: круглые скобки — узел, квадратные — связь, стрелка — направление.
- Метка в паттерне ограничивает область поиска; паттерн без метки означает полное сканирование графа.
- Одно ребро не может использоваться в паттерне дважды — это правило уникальности связей защищает от циклов и объясняет неожиданно пустые результаты.
- Паттерн внутри `WHERE` и `NOT (...)` заменяет `EXISTS`-подзапросы SQL, а `EXISTS {}` нужен, когда внутри требуется дополнительное условие.
- `OPTIONAL MATCH` — аналог `LEFT JOIN`, не может стоять первым и заставляет учитывать `null` во всём, что идёт следом.
- Группировка при агрегации происходит неявно по неагрегированным выражениям в `RETURN` — конструкции `GROUP BY` в Cypher нет.
- `count(x)` игнорирует `null`, `count(*)` считает строки — разница проявляется сразу после `OPTIONAL MATCH`.
- Значения передаются параметрами `$param`: это защищает от инъекций и позволяет переиспользовать план запроса.
