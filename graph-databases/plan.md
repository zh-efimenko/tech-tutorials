# Программа обучения: графовые базы данных

## Цель

Освоить графовые базы данных на уровне внедрения в проект: понимать, где графовая модель выигрывает у реляционной, проектировать схему графа, писать и оптимизировать Cypher, интегрировать Neo4j со Spring Boot, применять графовые алгоритмы к рекомендациям, антифроду и анализу зависимостей, строить knowledge graph и GraphRAG.

Это не один курс, а шесть последовательных треков. Треки 1-3 строят базу на сквозном примере, треки 4-6 решают прикладные задачи на уже построенном графе.

## Требования

- Docker Desktop (`compose.yml` в корне программы)
- Java 25, Spring Boot 4.1.x, Gradle 9.x — начиная с трека 3
- Понимание SQL и реляционного моделирования — для сравнений
- Опыт работы со Spring Boot — начиная с трека 3

## Запуск окружения

```bash
# Треки 1-5
docker compose up -d

# Трек 6 — дополнительно поднимает Ollama
docker compose --profile rag up -d

# Neo4j Browser: http://localhost:7474 (neo4j / graphpassword)
# Bolt для драйверов и cypher-shell: bolt://localhost:7687

# Подключение через CLI:
docker exec -it neo4j cypher-shell -u neo4j -p graphpassword
```

Первый запуск занимает около минуты: контейнер ставит плагины APOC и GDS, jar-файлы которых лежат внутри образа.

## Сквозной пример

Все треки работают с одной моделью — интернет-магазин с социальным слоем.

```
        FOLLOWS
      ┌──────────┐
      ▼          │
   (User) ───────┘
      │  │  │
      │  │  └─── WROTE ──▶ (Review) ── ABOUT ──▶ (Product)
      │  │                                            ▲
      │  └────── VIEWED ──────────────────────────────┤
      │                                               │
      └── PLACED ──▶ (Order) ── CONTAINS ─────────────┤
                                                      │
   (User) ── LOGGED_IN_FROM ──▶ (Device)     IN_CATEGORY
   (User) ── PAID_WITH ──▶ (PaymentMethod)            │
   (User) ── SHIPPED_TO ──▶ (Address)                 ▼
   (User) ── REFERRED ──▶ (User)                 (Category) ── SUBCATEGORY_OF ──▶ (Category)
                                                 (Brand) ◀── MADE_BY ── (Product)
```

Схема растёт от урока к уроку: урок 04 вводит `User`, `Product`, `Order` и связи `PLACED`/`CONTAINS`, урок 09 загружает полный датасет, урок 11 добавляет узлы-события, временную структуру и денормализованную связь `PURCHASED` как оптимизацию, трек 6 добавляет текстовые описания и векторные свойства. Новый трек не создаёт свой граф, а работает с тем, что построено раньше.

Одно исключение: урок 33 про анализ зависимостей и data lineage использует отдельный небольшой граф сервисов — этот класс задач в модель магазина не ложится. Граф загружается одним скриптом внутри урока.

## Рекомендуемый порядок

Треки 1 и 2 обязательны для всего остального — там модель данных, язык и производительность. Трек 3 нужен перед треками 5 и 6, потому что там появляется Java-код. Трек 4 самодостаточен сразу после треков 1-2: если нужны только графовые алгоритмы без интеграции, можно идти по маршруту 1 → 2 → 4 → 5.

Уроки внутри трека проходить строго по порядку и выполнять практику в `cypher-shell` или Neo4j Browser — задания следующего урока опираются на данные, созданные в предыдущем.
