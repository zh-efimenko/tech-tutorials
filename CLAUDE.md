# tech-tutorials — Claude Context

## Что это

Личный образовательный проект. Практические курсы по технологиям Java/Spring Boot стека. Всё содержимое на русском языке.

## Курсы

| Директория | Технология | Уроков |
|---|---|---|
| `archunit` | ArchUnit — архитектурные тесты Java/Spring | 10 |
| `clickhouse` | ClickHouse — колоночная СУБД | 11 |
| `gradle/toml` | Gradle Version Catalogs (TOML) | 8 |
| `graph-databases` | Neo4j — графовые БД, Cypher, GDS, GraphRAG (шесть треков) | 39 |
| `hazelcast` | Hazelcast — in-memory data grid | 12 |

| `AI` | Гайды по MCP и промптингу (не курс) | — |

## Структура каждого курса

```
{topic}/
├── plan.md                  — программа: цель, требования, таблица уроков
├── compose.yml              — Docker-окружение (если нужно)
├── 01_snake_case_name/
│   └── README.md            — единственный файл урока
├── 02_snake_case_name/
│   └── README.md
└── ...
```

Папки уроков: `NN_snake_case_name/` — двузначный номер, нижнее подчёркивание, lowercase.

## Структура урока (README.md)

```markdown
# Урок N. Название

## Что такое X / Зачем нужен X
1-3 абзаца: определение, проблема, зачем

## Основные секции (теория + примеры)
концепция → пример кода → пояснение

## Практика
5-8 конкретных заданий (действия, не вопросы)

## Итоги урока
5-8 буллет-пойнтов — самодостаточные утверждения
```

## Стиль и конвенции

**Язык:** текст — русский; код, команды, идентификаторы — английский; комментарии в коде — русский.

**Тон:** обращение на «ты», прямо, практично, без воды, без эмодзи.

**Подача:** сначала «зачем», потом «как». Сравнения с PostgreSQL/Redis/знакомыми инструментами. Блоки `>` или **Важно**/**Внимание** для подводных камней.

**Форматирование:**
- Таблицы — для сравнений и перечислений параметров
- ASCII-диаграммы в ` ``` ` блоках — для архитектуры и потоков данных
- Блоки кода — всегда с языком: `sql`, `java`, `groovy`, `yaml`, `bash`, `toml`, `xml`
- `##` — основные разделы, `###` — подразделы
- **Жирный** — ключевые термины при первом упоминании
- Курсив — не используется

**Примеры кода:** реалистичные (аналитика, ставки, пользователи, события), рабочие (можно скопировать и запустить). SQL — ключевые слова UPPERCASE, таблицы/колонки lowercase.

**Версии в примерах:** проверять запросом к реестру, а не по памяти — `maven-metadata.xml` на repo1.maven.org и plugins.gradle.org, `services.gradle.org/versions/current` для Gradle. Модель уверенно называет версии, которых не существует: в `gradle/toml` до проверки стояла несуществующая `mapstruct 1.6.4`. Апгрейд мажорной версии проверять и на переезд координат: Spring Boot 4 → Jackson 3 в группе `tools.jackson`, `starter-aop` → `starter-aspectj`; Testcontainers 2 → `org.testcontainers:testcontainers-postgresql`.

**Тексты ошибок и вывод команд:** воспроизводить на актуальной версии инструмента и копировать фактический вывод. Сообщения Gradle/CLI меняются между версиями, а в уроке они подаются как точное ожидание — это то, обо что студент спотыкается первым.

**НЕ делать в уроках:**
- Секции «Введение» или оглавление
- «В этом уроке мы рассмотрим...» / «мы узнали...»
- Дублировать информацию между уроками
- Создавать Docker/compose файлы или код проекта без явного запроса
- Добавлять ссылки на внешнюю документацию без крайней необходимости

## Стек, предполагаемый у аудитории

Java 17–25 · Spring Boot 3.x–4.x · Gradle 8.x–9.x · Docker Desktop · PostgreSQL · Redis · Kafka · Hazelcast

## Создание нового курса

Использовать skill `create-course` — там полный шаблон plan.md, правила, и процесс по шагам.

## Проверка курса

Использовать skill `verify-course` — цикл независимых прогонов субагентом-студентом со сбором находок и правками. Применять после написания курса и после существенных изменений: автор не видит собственных ошибок, потому что молча чинит их на ходу.

## Подход к работе

- Читать релевантные файлы перед предложением изменений. Не спекулировать о непроверенном коде.
- Вносить только явно запрошенные изменения. Без «улучшений» сверх задания.
- Следовать существующим конвенциям курса — читать соседние уроки перед написанием нового.
- Независимые инструменты вызывать параллельно (чтение нескольких файлов — одновременно).
- Если задача неразумна или невыполнима — сообщать, а не работать в обход.
